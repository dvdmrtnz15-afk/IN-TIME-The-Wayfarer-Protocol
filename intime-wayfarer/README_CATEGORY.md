# IN-TIME — Causal Strategy RPG design + Codex handoff

## Read first

This package adds a coherent design and new execution brief to the preserved existing game. **It does not implement the new category-proof features.** The delivered source/release remains v0.1.0. The previous v0.2 handoff is preserved unchanged and its verification obligations remain relevant.

- `CATEGORY_BLUEPRINT.md` — complete game/category synthesis, player experience, AI boundaries, strategy, RPG progression, first proof, and primary references.
- `CODEX_CATEGORY_GOAL.md` — the bounded next implementation assignment and C01–C16 acceptance gates.
- `CATEGORY_START.txt` — copy-ready `/goal` objective for a Codex version that supports Goals.
- `CATEGORY_PACKAGE_RECEIPT.json` and `CATEGORY_HANDOFF_MANIFEST.json` — package custody and verification of preserved input files, with any fresh baseline checks scoped explicitly.

Open this `intime-wayfarer/` folder as the Codex workspace. Read the new blueprint; then use the new goal when ready to implement. ChatGPT download paths do not automatically provide Codex file access. Do not overwrite a newer local project with this source; compare and continue it.

The old `CODEX_GOAL.md` remains the v0.2 stabilization assignment. The new `CODEX_CATEGORY_GOAL.md` governs the proposed expanded scenario only when selected for execution. Its scope-resolution section preserves the original game's invariants and quality gates.

## What is in the supplied game now

Read `README.md`, `PROVENANCE.md`, and `VERIFICATION.md`. Recorded echoes, the three classic puzzles, authored dialogue, seeded modifiers, and the standalone renderer are existing foundation features. The adaptive companion, Tactic Weaving, district economy, and limited forecast are proposed work, not shipped functionality.

Open `dist/IN_TIME_PLAY.html` in a browser that executes local JavaScript to try the preserved foundation, or use:

```sh
npm test
npm run build
npm start
```

No runtime account, model API, paid service or external asset is required.

## Codex Goals reference

OpenAI's official Goals documentation describes a persistent objective subject to permissions, budget, and stopping conditions. This package supplies an objective; it does not start a Codex session or configure any external automation.

https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex

## Release boundary

No upstream app changed, no remote repository created, no code pushed, no publication, and no deployment performed by preparation of this handoff. Category recognition, fun, human usability, hardware coverage, and market demand remain unestablished.
